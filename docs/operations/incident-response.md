# Incident response

Severity 1: data exposure, payment/ledger corruption, or total outage. Severity 2: checkout or queue degradation. Severity 3: isolated non-financial feature failure. Severity 4: cosmetic or documentation issue.

The incident commander opens a timeline, assigns communications and technical owners, freezes releases for Sev 1/2, preserves logs, and records every mitigation. Financial incidents require payment/reconciliation owner review. Close only after monitoring is stable, data is reconciled, customer impact is assessed, and a post-incident review has an owner and due date.
